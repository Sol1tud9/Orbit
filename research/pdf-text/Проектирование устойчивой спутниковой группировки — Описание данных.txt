Состав данных и начало работы
Один файл JSON содержит один проект группировки и условия его расчёта. Для начала
работы используйте 01_full_constellation.json. Сервис загружает файл, отображает
параметры и рассчитывает состояние сети на заданном периоде. Изменение настроек
в интерфейсе создаёт новый вариант проекта.
ФАЙЛ СОДЕРЖАНИЕ
01_full_constellation.json 48 аппаратов, три плоскости, три наземных пункта и один
шлюз. Расчёт на сутки.
02_first_launch.json Тот же проект на первой очереди запуска: активны 16
аппаратов.
03_satellite_outages.json Десять аппаратов недоступны с шестого часа до конца
расчёта.
04_link_range.json Полная группировка при дальности межспутниковой связи
2000 км.
Формат файлов — JSON, кодировка UTF-8. Время отсчитывается от начала расчёта в
секундах. Идентификаторы связывают объекты внутри файла. Сценарий может
содержать другие названия и идентификаторы при сохранении структуры данных.

ОБЪЕКТ И ПОЛЕ НАЗНАЧЕНИЕ
satellites[].slot_deg Начальное угловое положение спутника внутри плоскости,
градусы. К нему прибавляется phase_deg.
satellites[].launch_batch Очередь запуска спутника: 1, 2 или 3.
В полной конфигурации заданы три плоскости по 16 аппаратов. RAAN определяет
ориентацию плоскости, phase_deg — положение спутников вдоль неё. При сравнении
проектов пользователь меняет эти параметры и выбранную очередь запуска; состав
файлов позволяет сохранять весь вариант целиком.
Наземные пункты и периоды недоступности
Каждый элемент ground_sites содержит id, name, role, lat_deg и lon_deg. role принимает
значение client для обслуживаемого пункта или gateway для шлюза. Широта задаётся в
диапазоне от −90 до 90° , долгота — от −180 до 180° . Идентификаторы наземных пунктов
и спутников должны различаться.
Событие failures задаётся полями satellite_id, start_s, end_s. Для gateway_outages
используются gateway_id, start_s, end_s. Начало интервала включается, конец
исключается. Пересекающиеся интервалы объединяются по смыслу недоступности.
Например, период [21 600; 43 200) действует с шестого до двенадцатого часа.
Правила расчёта
Модель использует круговые орбиты и сферическую Землю. Положение спутников
рассчитывается непрерывно, состояние связей проверяется на заданной сетке
времени. Для наземной линии применяется единый порог угла возвышения.
Межспутниковый контакт определяется дальностью и отсутствием пересечения линии
связи с Землёй.
Координаты спутников
Константы: радиус Земли R = 6371 км; гравитационный параметр μ = 398600,435507
км³/с²; период вращения Земли T = 86164,09054 с. Для высоты h радиус орбиты r = R +
h, угловая скорость n = √(μ/r³). Перед расчётом углы переводятся из градусов в
радианы.
Пусть Ω — raan_deg плоскости, i — inclination_deg, u(t) = slot_deg + phase_deg + n·t, где
оба угла в сумме переведены в радианы. Координаты спутника в инерциальной
системе:
x = r·(cos Ω·cos u − sin Ω·sin u·cos i)
y = r·(sin Ω·cos u + cos Ω·sin u·cos i)
z = r·sin u·sin i

Наземные и межспутниковые контакты
Координаты наземного пункта широты φ и долготы λ: g = R·(cos φ·cos λ, cos φ·sin λ, sin
φ). Для спутника с земными координатами s угол возвышения равен arcsin(((s − g)·g)/
(‖s − g‖·R)). Результат arcsin переводится в градусы. Наземный контакт доступен при
угле не меньше min_elevation_deg и активном спутнике. Для линии со шлюзом
дополнительно учитывается его доступность.
Для двух активных спутников с координатами a и b контакт доступен при ‖b − a‖ <
isl_range_km и расстоянии от центра Земли до отрезка [a; b] больше R. Для проверки
отрезка положите d = b − a, q = clip(−a·d/(d·d), 0, 1); ближайшая точка равна a + qd. При
совпадении координат используется расстояние ‖a‖.
Контакты двунаправленные. Маршрут начинается в выбранном client, проходит через
один или несколько активных спутников и заканчивается в доступном gateway.
Промежуточные узлы маршрута — спутники. Недоступный аппарат сохраняет
расчётное положение и исключается из состава связей на период отказа.
Каждый маршрут рассматривается для текущего отсчёта времени. Основные
показатели характеризуют геометрическую доступность пути. Расчёт пропускной
способности, очередей передачи и задержки ожидания контакта команда может
добавить отдельным функционалом.
Показатели результата
Для каждого наземного пункта необходимо рассчитывать долю времени видимости
хотя бы одного активного спутника, долю времени наличия пути до шлюза и
максимальную длительность перерыва. Доли равны числу соответствующих отсчётов,
делённому на общее число отсчётов. В интерфейсе они отображаются в процентах.
Максимальный перерыв — самая длинная последовательность отсчётов без пути,
умноженная на step_s. Перерывы в начале и конце периода учитываются отдельно.
Число переходов маршрута равно числу его рёбер и включает две наземные линии.
При отсутствии пути значение числа переходов отсутствует.
Показатели выводятся по каждому пункту. Сравнение показывает одинаковый период
и принятые изменения конфигурации. Параметры высоты, дальности и угла
возвышения сохраняются для сопоставления проектных вариантов; исследование
других значений оформляется отдельным запуском с отображением новых условий.

Сохранение и выгрузка
Выгружаемый результат содержит schema_version со значением cosmo-A-result-1.0,
effective_scenario с полным использованным сценарием и routes со списком
маршрутов. Для каждой пары «момент расчёта — наземный пункт» должна
присутствовать одна запись с полями t_s, client_id и path.
{"t_s": 120, "client_id": "C65", "path": []}
path содержит последовательность идентификаторов от наземного пункта до шлюза;
пустой список означает отсутствие построенного маршрута. К результату можно
добавить сводные показатели и пояснения. Сохранённые настройки должны включать
изменения, выполненные пользователем перед запуском.
Проверка входа
Числовые значения должны быть конечными, идентификаторы — уникальными в
соответствующих списках. Ссылки на плоскости и аппараты должны разрешаться.
Продолжительность и шаг задаются целыми положительными секундами,
продолжительность кратна шагу. Все интервалы недоступности расположены внутри
периода расчёта и имеют положительную длительность. При ошибке сервис указывает
проблемное поле или объект.
