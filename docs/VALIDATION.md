# Проверка корректности и выпуска

Проверено 12 сентября 2026 года. Достоверность геометрии обеспечивается прямым вызовом неизменённого `geometry.py`, а достоверность собственной логики — независимыми графовыми оракулами, тестами метрик и интеграционными проверками.

## Автоматические проверки ядра

`python -m pytest -q`: **88 passed**. Проверены:

- Все 2880 snapshots четырёх исходных сценариев и 8640 пар клиент/время: достижимость и минимальные hops сравнены с отдельной реализацией Floyd–Warshall, каждое ребро выбранного пути принадлежит эталонным контактам, внутренние узлы — активные спутники.
- Оптимальность длины среди минимальных hops и детерминированный tie-break сравнены с полным перебором простых путей на малых случайных графах.
- Метрики перерывов проверены Hypothesis против независимого оракула по булевым последовательностям; начало и конец горизонта не объединяются.
- Новый набор ID и два gateways, отключение обоих, события вне сетки, перекрывающиеся отказы, отсутствие наземного транзита, отмена и неизменяемость исходного сценария.
- Некорректные поля/ссылки, повторные ключи JSON, bool, нечисловые/бесконечные значения, структурные ограничения и сохранение расширений.
- API-сеансы, чужой run ID, экспорт, индексы, перезапуск, настоящее задание в отдельном процессе, гонка завершения и отмены.

Ruff и TypeScript `--noEmit` проходят. Production-сборка Vite проходит; зависимости frontend зафиксированы в package-lock.

## Исследовательские проверки модели

До реализации выполнены скалярная сверка геометрии по формулам PDF на 60 изменённых состояниях, проверки строгих порогов, отказа в 21600 с, окончания в 86400 с, переименований и перестановок. Материалы и результаты сохранены в `research`. Это дополнительные исследовательские запуски; не все они оформлены как отдельные pytest-тесты. Численное совпадение геометрии не заменяет проверку маршрутов и метрик.

## Проверка контейнера

Образ собран из Dockerfile и запущен через Compose. Через настоящий HTTP API рассчитаны четыре исходных и один новый сценарий. Сверены все контрольные показатели, исходный effective_scenario, количество записей экспорта, отключение двух шлюзов и изоляция сеансов. После перезапуска контейнера проверено чтение всех пяти готовых результатов.

Повторение:

```powershell
python tests/verify_deployment.py --url http://127.0.0.1:18000
docker compose -p orbita-verify restart app
python tests/verify_deployment.py --resume --url http://127.0.0.1:18000
```

Первый вызов сохраняет служебный cookie проверки только в игнорируемом `var/deployment-check.json`. Измерения без cookie: [deployment-measurements.json](deployment-measurements.json). В текущем локальном прогоне полные сценарии занимали примерно 4–6 секунд от отправки до получения экспорта. Это измерение одной машины, не SLA и не нагрузочный тест.

## Сквозная проверка UI

`web/tests/workspace.spec.ts` покрывает четыре исходных сценария, смену клиента, навигацию к перерыву, JSON-экспорт, восстановление расчёта и выбранного названия сценария, новый сценарий с кириллическим ID и двумя gateways, ошибочный ввод, модальное окно и ширины 1280/390. **3 passed за 36,3 с** на Chromium Headless 153. Первый запуск до установки браузера завершился ошибкой отсутствующего executable; после установки все тесты прошли. На полном сценарии также сохранён и визуально проверен [снимок интерфейса](preview.png).

Ручной сценарий защиты текущего пакета: полный вариант → доступность C65 и маршрут → ISL 2000 → C70 и первый разрыв сети → timeline и топология → новый JSON → экспорт. Встроенное изменение параметров, A/B и рекомендации относятся к следующим этапам.

## Ограничения доказательств

Тесты подтверждают дискретную модель и реализованные операции, а не физическую пригодность реальной радиосети. CI-конфигурация подготовлена; удалённый GitHub Actions запуск не заявляется выполненным. Внешний сервер пока не выбран, поэтому HTTPS-конфигурация подготовлена, но реальная публичная ссылка ещё не проверена. Нагрузочные тесты больших сценариев и полный UX-аудит остаются критериями финального выпуска.
