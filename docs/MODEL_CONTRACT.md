# Контракт модели и данных

Главный источник требований — три PDF организаторов и `Расчетный модуль/geometry.py`. Их содержимое не изменено. SHA-256 geometry: `2f7dc14f7e826c2815bbbb2ecbd67ef26e81f092b15c06e197b31dd3ff66daf6`.

## Геометрия

Ядро напрямую вызывает исходный `snapshot(scenario, t_s)` через адаптер. Координаты, активность, наземные и ISL-контакты не вычисляются повторно в браузере. Земля сферическая, радиус 6371 км; круговые орбиты; μ = 398600.435507 км³/с²; период вращения Земли 86164.09054 с. Радиобюджет, атмосфера, J2, трафик и ёмкость каналов не добавлены.

Координаты snapshot — земная система отсчёта. Неактивные аппараты сохраняют координаты. Контакт с наземным пунктом существует при угле возвышения **не меньше** порога; межспутниковый — при расстоянии **строго меньше** `isl_range_km` и расстоянии от центра Земли до отрезка **строго больше** радиуса. Пороговые неравенства не смягчаются допуском.

Аппарат активен, если `launch_batch <= launch_stage` и время не принадлежит ни одному интервалу отказа `[start_s, end_s)`. Аналогичная полуоткрытая семантика у отключения шлюзов. Очередь запуска — условие всего расчёта, а не событие внутри суток.

## Вход

Версия `cosmo-A-1.0`. Машиночитаемая схема: [scenario.schema.json](scenario.schema.json); дополнительная межполевая валидация реализована в `orbita/scenario.py` и эталоне. API возвращает путь ошибочного поля и сообщение.

Сохраняются все дополнительные поля и исходные числовые значения; не подставляются неявные defaults. Сценарий копируется перед расчётом. Проверяются обязательные поля, диапазоны, ссылки на плоскости/спутники/шлюзы и глобальная уникальность идентификаторов. Допускаются произвольные имена, количества и несколько gateways. Клиенты и gateways определяются по роли, а не названию.

Намеренное ужесточение структурной проверки: обязательна `meta`, bool не принимается вместо числа, отсутствующие поля дают понятную ошибку, повторяющиеся JSON-ключи запрещены. Это устраняет пробелы валидатора эталона, не меняя геометрию. `launch_batch=1.0` принимается, как эталоном; очередь расчёта и сетка требуют целых значений. NaN/Infinity, числовые литералы длиннее 309 цифр и глубина JSON более 128 отклоняются как технически неподдерживаемый ввод. HTTP-загрузка ограничена 10 МБ.

## Время и показатели

Сетка `range(0, horizon_s, step_s)`; горизонт кратен шагу. Последняя точка суток при шаге 120 с — 86280 с, а не 86400 с. Событие `[61,181)` влияет на отсчёт 120 с, но не 0 или 240 с.

- Покрытие клиента — доля отсчётов с хотя бы одним видимым активным спутником.
- Доступность — доля отсчётов с допустимым путём до любого работающего gateway.
- Перерыв — последовательность отсчётов без пути; длительность равна их количеству × шаг. Начало и конец горизонта не склеиваются циклически.
- Смена причины внутри перерыва не создаёт новый перерыв. Причины подсчитываются отдельно.
- Переходы включают оба наземных ребра. Средняя длина и hops вычисляются только по существующим маршрутам; при отсутствии маршрутов возвращается `null`.
- Переключение маршрута считается между соседними связанными отсчётами, если полная цепочка ID изменилась.
- Цель проверяется отдельно для каждого клиента, без усреднения между пунктами. Достижение цели всеми клиентами — отдельный флаг.

Показатели описывают заданную дискретную сетку. Они не доказывают непрерывность связи между отсчётами.

## Маршрутизация и причины

Граф неориентированный. Внутренние узлы пути — только активные спутники. Клиент служит источником, работающий gateway — конечной точкой; наземный транзит запрещён.

Критерий: минимум рёбер, затем минимум суммы длин рёбер, затем лексикографический порядок полной цепочки ID. BFS строит уровни, проход по полученному DAG выбирает кратчайшую длину среди путей с минимальным числом рёбер. Нельзя улучшить число переходов более длинным по уровням путём; внутри DAG аддитивная длина позволяет динамическое программирование. Независимые проверки сравнивают результат с Floyd–Warshall и полным перебором простых путей на малых графах. Это критерий проектного решения: документы не задают порядок tie-break.

Основная причина определяется по порядку: путь есть → нет покрытия клиента → все gateways отключены → работающие gateways не имеют спутниковых контактов → разрыв спутниковой сети. Если одновременно действуют несколько условий, API также возвращает факты: видимые аппараты, работающие шлюзы, компоненты и контакты. Эти категории объясняют состояние, но сами по себе не доказывают причинный вклад конкретного отказа; контрфактический анализ запланирован отдельно.

## Выход и воспроизводимость

Обязательный экспорт имеет версию `cosmo-A-result-1.0`, полный `effective_scenario` и `routes`: ровно одна запись `{t_s, client_id, path}` на клиента и отсчёт; отсутствие пути — `[]`. Дополнительные `summary` и `provenance` содержат метрики, версию ядра, SHA-256 эталона/сценария и политику маршрутизации. Внутренний артефакт `orbita-run-1.0` дополнительно хранит ряды и сетевые агрегаты.

SHA сценария вычисляется по JSON с сортированными ключами. Порядок массивов и числовое представление сохраняются: физически эквивалентные файлы могут иметь разные hashes, что допустимо для учёта исходных ревизий. Время выполнения не участвует в проверке математической идентичности.
