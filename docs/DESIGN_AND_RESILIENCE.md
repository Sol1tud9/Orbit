# Проектирование, сравнение и устойчивость

## Редактор и ревизии

Формы покрывают окружение, очередь, RAAN/фазы плоскостей, состав спутников, наземные пункты и интервалы событий. Строки можно добавлять и удалять. При переименовании объектов связанные ID также должны оставаться корректными: сервер указывает нарушенные ссылки при сохранении. Неизвестные дополнительные поля JSON сохраняются.

«Сохранить ревизию» проверяет JSON и записывает отдельную версию с родительским ID. Библиотека позволяет открыть её снова и скачать полный JSON. «Применить к рабочей области» сохраняет ревизию и открывает её без метрик предыдущего расчёта. Старые расчёты остаются в истории. «Сбросить правки» возвращает исходное состояние редактора. Перед перезагрузкой страницы несохранённые изменения нужно сохранить.

## Сравнение

Выберите два завершённых расчёта. Проверяются горизонт, шаг, клиентские ID/координаты, геометрия и политика маршрутизации. При несовместимости показываются причины и diff вместо численных дельт. Подготовка B на сетке A меняет только горизонт и шаг в редакторе; интервалы событий проходят обычную проверку без скрытого обрезания.

Дельты — B − A. Для каждого клиента показаны доступность, восстановленные/потерянные отсчёты и максимальные перерывы. Цветовая полоса переносит к изменившемуся моменту. Курсор, воспроизведение, представление, камера и фильтры связей синхронизированы. Экспорт содержит IDs расчётов, diff, правила сопоставимости и метрики; исходные сценарии доступны из истории каждого run.

## Визуализация и диагностика

Глобус использует серверные ECEF-координаты, радиус Земли 6371 км и масштабную высоту. Вращение камеры не меняет состояние сети. Обратная сторона скрывает узлы и участки контактов. Деление линий на 40 отрезков используется только для отрисовки, без изменения контактов ядра. Полярная карта полезна для Арктики, граф — для полного маршрута через оба полушария. Все режимы работают без WebGL и внешних CDN.

Timeline показывает весь горизонт либо окно ×4/×12 около выбранного отсчёта. Клики, ввод и переходы остаются на исходной сетке; нумерация отсчётов начинается с 1. Контакты доступны в таблице с поиском по ID. Длинная цепочка прокручивается внутри инспектора, узлы графа выбираются с клавиатуры.

Следующий допустимый путь выбирается как лучший из результатов исключения каждого ребра основного маршрута. Любой отличающийся путь не содержит хотя бы одного ребра основного, поэтому такой поиск находит лучший альтернативный путь по принятому критерию. Он может использовать общие спутники. Отдельно для каждого внутреннего узла основного пути проверяется обход после его удаления. «Задать отказ» открывает вариант с отказом от выбранного времени до конца горизонта.

Контрфактическая проверка убирает все объявленные отказы спутников и шлюзов в выбранном отсчёте. Восстановление доказывает достаточность их совместного устранения в этот момент, но не индивидуальный вклад отдельного события.

## Обновлённая рабочая среда

Основные режимы вынесены в боковую навигацию; на узком экране они располагаются над сценарием. Светлая рабочая область отделяет параметры и результаты от тёмной сцены сети. По умолчанию открывается глобус. Карта и топология доступны рядом с ним. Цвет и подписи состояния согласованы с маршрутом и временной шкалой.

Служебные обозначения формата и название мероприятия убраны с экрана. Сохранённые расчёты различаются по названию и времени создания. В A/B текущий расчёт первоначально выбирается как новый вариант B, предыдущий — как база A; оба выбора можно изменить. На телефоне широкие таблицы прокручиваются внутри панели, а основные действия остаются доступными.

Для первого знакомства с расчётами: [объяснение с нуля](HOW_IT_WORKS.md).

## N−1 и рекомендации

Каждый развёрнутый аппарат получает дополнительный отказ на весь горизонт поверх исходных событий. Snapshot вычисляется один раз на отсчёт, затем удаляются аппарат и его рёбра. Это эквивалентно отдельному геометрическому пересчёту в заданной модели: контакты других пар не зависят от третьего аппарата. Эквивалентность проверена отдельными полными пересчётами.

Каждый случай заново получает пути и метрики по всем клиентам. Сортировка: максимальная потеря у отдельного клиента, затем сумма потерь и ID. Случай можно открыть как сценарий отказа и проверить обычным расчётом. Для полной группировки проверены 48 аппаратов × 720 отсчётов: первая строка по принятой сортировке — S44, потери 17/14/14 отсчётов у C65/C70/C72. [Измерение и независимая сверка](resilience-measurements.json). Это дискретные показатели, а не вероятность физического отказа.

Рекомендации полностью пересчитывают ограниченный набор: устранение объявленных отказов, следующая очередь, увеличение ISL на 1000/2000 км в пределах спецификации. «Улучшение подтверждено» означает наличие восстановленных отсчётов без потерянных отсчётов у всех клиентов. Достижение цели показывается отдельно. Каждая карточка содержит метрики и ограничение интерпретации; кандидат открывается в редакторе.

JSON-отчёт содержит исходный сценарий, ID базы, результаты случаев, hashes, версии, длительности и политику эксперимента. Для воспроизведения N−1 добавьте к исходному сценарию отказ указанного аппарата на весь горизонт. Глобальный оптимум, радиобюджет и экономическая эффективность не заявляются.

Эксперименты используют общий ограниченный пул процессов, отдельную историю, progress и отмену. Частичный результат не выдаётся за итоговый. Готовые отчёты сохраняются после рестарта; незавершённые задания помечаются прерванными. Бюджет `ORBITA_MAX_EXPERIMENT_WORK` — 200 млн по умолчанию; дополнительно максимум 250000 комбинаций кандидат × отсчёт × клиент. Превышение даёт понятную ошибку, не обрезает результат.
